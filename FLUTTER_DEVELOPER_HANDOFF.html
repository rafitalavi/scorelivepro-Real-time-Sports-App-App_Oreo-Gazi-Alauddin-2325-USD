1. Champions League 9-Match Bug & League Grouping

Issue Reported: ScoreLivePRO was showing 9 matches in the "Champions League" section, including matches that do not belong to the UEFA Champions League (such as Foresters vs Wiliete). Diretta only shows 6 matches.

Root Cause

On September 10, 2026, 9 total matches occur across distinct tournaments containing the string "Champions League":

  • UEFA Champions League (ID 2): 6 matches (PSV vs Shakhtar, Bayern vs Bodo/Glimt, etc.)
  • CAF Champions League (ID 12): 1 match (Foresters vs Wiliete - African Preliminary Round)
  • Nasjonal U19 Champions League (ID 823): 2 matches (Norway Youth)

The Flutter app was grouping matches by league.name or using a substring check .contains("Champions League"), collapsing all 3 separate competitions into a single accordion card.

Action Required in Flutter

Option A (Recommended): Consume the new pre-grouped endpoint:

GET /sports/fixtures/grouped/?date=YYYY-MM-DD

Option B: If continuing with local grouping from GET /sports/fixtures/?date=..., group strictly by league.id (integer):

// ❌ WRONG (Causes 9-match collision):
final groupKey = match.league?.name;

// ✅ CORRECT (Strict tournament isolation):
final int leagueId = match.league?.id ?? 0;
final groupKey = "${leagueId}_${match.league?.name ?? ''}";

2. Confederation & Continental Region Localizations

You can now delete all hardcoded maps of tournament IDs in Dart. Every league object now carries native continental classifications and localized translations across 7 languages (en, it, es`, `fr`, `de`, `pt`, `tr`):

// Updated Dart Model Usage
String getHeaderCountry(LeagueModel league, String userLangCode) {
  if (league.country?.name == "World" || league.country?.name == "International") {
    // Returns "Europa" (it), "Europe" (en), "Afrique" (fr), etc.
    return league.localizedRegion?[userLangCode] ?? league.region ?? "World";
  }
  return league.country?.name ?? "";
}

3. Upcoming Matches & Strict Date Bounding

Leakage Resolved: Calling GET /sports/fixtures/?status=upcoming previously returned fixtures spanning 15 days ahead (up to 74 future UCL fixtures).
  • With Date: GET /sports/fixtures/?status=upcoming&date=YYYY-MM-DD strictly filters matches to that date.
  • Without Date: GET /sports/fixtures/?status=upcoming now automatically caps results to the next 24 hours (now + 24h).
  • You can remove the client-side _isMatchOnDate pruning logic.

4. Fixture Coverage Metadata

Every fixture response now contains a coverage object indicating whether official lineups, statistics, or match events exist:

"coverage": {
  "lineups": false,
  "statistics": false,
  "events": true
}

Flutter Action: Check fixture.coverage.lineups and fixture.coverage.statistics. If false, immediately render the empty state without firing redundant network requests.

5. Diacritic & Accent Search Normalization

The backend now uses PostgreSQL unaccent for team and league searches. You no longer need to strip accents or write custom regexes on the mobile app:

  • GET /sports/teams/?search=atletico → matches "Atlético Madrid" and "Alianza Atletico".
  • GET /sports/teams/?search=sao paulo → matches "São Paulo" and "Sao Paulo".
