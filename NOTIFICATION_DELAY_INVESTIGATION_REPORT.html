✅ Key Audit Finding: Sub-Second Backend Delivery vs. Upstream Scout Delay

The investigation conclusively proves that the ScoreLivePRO backend engine, Celery workers, and notification dispatch pipeline delivered notifications within 1.5 seconds of receiving the data.

The 13-minute delay originated upstream from the sports data provider (API-Football). In lower-tier competitions (such as Italian Serie C), stadium scouts frequently input substitutions retroactively in batches. When API-Football finally published the event at the 80th minute, it stamped the record with the pitch match time (67'). The app dispatched the alert instantly, creating the visual impression that the notification was held by the app.

2. Investigation: Upstream Data Provider (API-Football)

No Wall-Clock Timestamps in API Response

An audit of API-Football's schema reveals that the provider does not supply an absolute timestamp (e.g. 2026-09-13T20:23:44Z) for events. The payload only contains the match clock minute: 

{
  "time": { "elapsed": 67, "extra": null },
  "team": { "id": 26356, "name": "Union Brescia" },
  "player": { "name": "A. Mercati" },
  "assist": { "name": "M. Zennaro" },
  "type": "subst",
  "detail": "Substitution 1"
}

Hard Empirical Evidence from Production Database

A forensic scan of 1,109 second-half substitutions across live database records confirmed that API-Football routinely delays and batches events in lower-tier tournaments:

Match 1609025: Cosenza vs Cavese (Serie C)
31.9 Min Provider Delay

Substitutions for minute 59 (T. Petrovic and A. D'Alena) were completely omitted from the live feed during minutes 65, 73, and 88. API-Football finally pushed both substitutions at 14:52:58 UTC (Full Time), exactly 31.9 minutes after minute 59.

Match 1608266: Lumezzane vs Renate (Serie C)
25.7 Min Provider Delay

Substitutions from minute 70 were withheld by API-Football while minute 78 and 79 substitutions were published. The minute 70 substitutions only appeared in the feed at 17:57:37 UTC (Full Time).

Match 1590057: Dinamo Tirana vs Partizani
Single Batch Dump

At exactly 15:54:37 UTC, API-Football published five substitutions simultaneously: two from the 60th minute (delayed by 31.2 minutes) and three from the 81st minute (delayed by 10.2 minutes).

5. Identified Infrastructure Optimizations

⚠️ Actionable Backend Hardening Items
  1. Move `fetch_live_statistics` off High-Priority Queue: fetch_live_statistics currently loops with time.sleep(1.0) taking up to 188 seconds, occupying 1 of 4 worker processes. It should run on the standard celery queue.
  2. Adjust Lock TTL on `fetch_live_events`: Lock TTL is currently 40 seconds, which can expire prematurely when 35+ followed matches are live. Increase TTL to 120 seconds.
  3. Expand FCM Connection Pool: Increase HTTP adapter connection pool size from 10 to 30 to prevent Connection pool is full warnings during simultaneous multi-language topic fanout.
